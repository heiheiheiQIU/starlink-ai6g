# A1 legacy battery asset audit

Generated by `python -m training.inspect_legacy --config configs/legacy_assets.json --output-root .` from the frozen sibling package. Hashes and sizes are in `data/manifests/legacy.csv`; machine-readable details are in `data/manifests/assets_audit.json`.

## Confirmed

- All 7 configured assets match their unique package manifest SHA256 and size.
- Source NPZ: (585, 15, 11) windows, 20 runs, cycle steps and cycles labels.
- Target NPZ: (79710, 15, 11) windows, 100 runs, orbit steps and orbits labels.
- Source NPZ labels match the fixed CSV exactly for 585/585 comparable windows; missing=0.
- Strict CPU LSTM and BiLSTM-Attention checkpoints each produced raw normalized predictions for two distinct delivered windows. The first source window starts at index 0 and is available at index 14.
- Environment: Python 3.12.14; NumPy 2.1.3; PyTorch 2.5.1+cpu; CPU Intel64 Family 6 Model 183 Stepping 1, GenuineIntel.

## Conflicting lineage

- The original source CSV matches only 262/384 comparable NPZ labels, with 201 missing and maximum absolute difference 65.0. The fixed CSV matches all source NPZ labels. The legacy preprocessing entry point refers to the original CSV, so its lineage is not established by the delivered NPZ.

## Unverified boundaries

- No persisted scaler has been established for transforming new raw telemetry into the checkpoint feature space. Evidence uses only delivered standardized NPZ windows.
- Native online RUL restoration requires a future run maximum, so `rul_est` remains null. Raw normalized prediction must not be interpreted as SOC, capacity, energy, or online RUL.
- Target NPZ label lineage to its originating CSV and satellite operational validity remain unverified. These results are not new communication experiments.

## 1. 总目标

当前报告的文字、表格和公式已经形成主体，但缺少能够在 5—10 秒内帮助评委理解以下问题的高质量图形：

1. 6G 星地场景的真实业务矛盾是什么；
2. AI 在通信调度中具体做了什么；
3. 学习评分与硬约束执行如何解耦；
4. 协议、能量、窗口、确认与重传如何形成闭环；
5. 开发期与正式实验如何公平验证；
6. 结果、失败案例和证据如何追溯；
7. 从合成验证到真实试点的落地路线是什么。

本任务的目标不是把报告装饰得“更花”，而是用统一的 Nature 风格科研图形降低阅读成本、增强论证强度，并建立可复现的图形资产库。

最终目标：

- 报告正文保留 **10—13 张核心图**；
- 附录、PPT和答辩备份页保留 **6—9 张扩展图**；
- 每张定量图都可从原始数据一键复现；
- 每张机制图都能回溯到报告文字、合同或代码；
- 交付 SVG/PDF 矢量版和 PNG 预览版；
- 三人生成的图片放在一起时，字体、色调、留白、图例和标注像同一篇文章，而不是三个项目。

## 2. 不可突破的科学与材料边界

### 2.1 数据保真

- 不允许修改、平滑、补齐、筛选或重排数据以制造更好趋势；
- 不允许 AI 根据文字想象数值、误差棒、显著性或趋势；
- 不允许用前端演示 fixture 替代正式运行数据；
- 不允许把开发期规则矩阵写成正式实验；
- 不允许把训练 MSE、域内命中率写成调度收益；
- 不允许删除负结果、失败 run 或不利工况；
- 坐标范围、颜色范围、归一化方法和异常值处理必须写入 manifest。

### 2.2 结果口径

正式实验只允许四档：

- 胜；
- 等效档——只表示未检出稳定差异，不是严格统计等效；
- 负；
- 未完成。

截至本文生成时，`claim-X1`、`claim-X2`、`claim-X3` 仍为 pending，因此正式结果相关图只能生成**空模板和绘图脚本**，不得提前填入结果。

### 2.3 AI 使用边界

AI 可以：

- 帮助设计图形结构；
- 生成或优化 matplotlib/seaborn/Graphviz/draw.io 代码；
- 调整字体、配色、图例、网格和留白；
- 检查色盲友好、标签遮挡和格式一致性；
- 根据已经签核的事实生成定性机制图。

AI 不可以：

- 生成看似真实但没有源数据的统计图；
- 擅自修改图表类型以强化结论；
- 把示意图伪装成测量结果；
- 用生成式图片替代网络架构、算法流程和实验结果；
- 自动添加不存在的模块、接口、传感器或验证阶段。

## 3. 图形资产目录和命名规则

建议建立以下目录：

```text
docs/figures/
├─ source/          # CSV、JSON、YAML、drawio、原始截图清单
├─ scripts/         # matplotlib、seaborn、Graphviz 绘图脚本
├─ vector/          # SVG、PDF 矢量图
├─ raster/          # 600 DPI PNG 和 1920px 演示预览图
├─ manifests/       # 每张图的数据来源与生成信息
└─ previews/        # 低体积审阅缩略图
```

命名规则：

```text
fig_<章节号>_<负责人>_<主题>_v<版本>.<格式>
```

示例：

```text
fig_03_A_teacher_label_audit_v1.svg
fig_04_B_formal_paired_effect_v1.pdf
fig_03_C_ai6g_coupling_v2.png
```

禁止使用：

```text
最终版.png
新建图片1.svg
好看的图.pdf
修改后2.png
```

## 4. 统一 Nature 风格视觉规范

这里的“仿 Nature”是指科研出版的克制、清晰、可复现和专业化，不是复制某一期刊的具体版式或品牌。

### 4.1 总体风格

- 白色或极浅灰背景；
- 丰富但低饱和的功能性色彩；
- 数据比装饰更突出；
- 尽量不使用渐变、阴影、3D柱状图和发光效果；
- 主图去除上、右边框；
- 网格线仅保留必要主网格；
- 多子图严格对齐，统一坐标轴、图例和色标；
- 图中文字简洁，解释放图注而不是塞进图区。

### 4.2 项目统一色板

以下色板由现有“航天任务控制台”色彩转化为适合白底报告的科研色板。

| 语义 | Hex | 用途 |
|---|---|---|
| 深轨道蓝 | `#24415A` | 主标题、EDF、框架主线 |
| 冰川青 | `#3D8EA3` | 星地链路、学习评分策略、当前动作 |
| 健康青绿 | `#4A9C81` | 健康、通过、成功交付 |
| 柔和琥珀 | `#D49A3A` | 能量约束、等待、边界工况 |
| 矿物珊瑚 | `#C96868` | 失败、负结果、违规、丢失 |
| 灰蓝紫 | `#7E86A8` | AI/教师、辅助策略、次级类别 |
| 中性深灰 | `#3D4650` | 正文、坐标轴、轮廓 |
| 雾灰 | `#DDE3E8` | 网格、背景分区、未完成状态 |

规则：

- 单张图最多 3—5 个主色；
- 同一策略在所有图中颜色固定：EDF=`#24415A`，Value=`#D49A3A`，Learned=`#3D8EA3`，Teacher/Oracle=`#7E86A8`，Idle=`#8C969F`；
- 健康状态使用青绿，能量使用琥珀，丢失/失败使用珊瑚；
- 颜色不是唯一编码，必须叠加线型、标记或文字；
- 连续正值默认使用 `cividis` 或 `viridis`；
- 正负差值默认使用以 0 为中心的 `RdBu_r` 或定制蓝—灰—珊瑚发散色板；
- 禁止 `jet`、彩虹色板和红绿二元编码。

### 4.3 字体

- 中文：思源黑体 / Noto Sans CJK SC；
- 英文与数字：Arial / Helvetica；
- 数学：STIX Two Math、Cambria Math 或 Times New Roman；
- 全图只允许上述两类主字体和一类数学字体；
- SVG/PDF 必须嵌入字体或将字体转为可编辑路径副本；
- 不使用楷体、书法体、圆体和系统随机替代字体。

报告双栏宽图建议字号：

| 元素 | 字号 |
|---|---:|
| 子图总标题 | 13—15 pt |
| 子图标题 | 10—11 pt |
| 坐标轴标题 | 9.5—10.5 pt |
| 刻度与图例 | 8.5—9.5 pt |
| 数据标签 | 8—9 pt |
| 来源/注释 | 7.5—8.5 pt |

### 4.4 尺寸和导出

- 报告单栏：8.5 cm；
- 报告双栏/整页：16.5—17.5 cm；
- 多子图优先 16:9、3:2 或 2:1；
- 热力图矩阵图区尽量接近正方形；
- 首选 `SVG + PDF`；
- 同步导出 600 DPI PNG 供 DOCX、预览和兼容性回退；
- PNG 使用白底，不保存透明背景；
- PDF 必须嵌入字体；
- 导出使用 `bbox_inches='tight'`，但不得裁掉图例、误差棒或脚注；
- 生成脚本必须固定随机种子、库版本和排序规则。

### 4.5 线条、标记和网格

- 主线 1.5—2.0 pt；
- 辅助线 0.8—1.2 pt；
- 网格 0.5 pt、`#DDE3E8`、alpha 0.5；
- 零线或约束阈值 1.2 pt，深灰虚线；
- 标记 4—7 pt；
- 置信区间使用半透明带，alpha 0.15—0.25；
- 不用粗黑边框围住所有元素。

### 4.6 子图编号

- 使用 `(a) (b) (c)`；
- 放在子图左上角，不遮挡数据；
- 字体 10—11 pt、Bold；
- 总图图注解释每个子图，不在图中重复长说明。

## 7. 成员 B：仿真、协议与正式实验图表任务

### B-F01 星地协议时序图

**优先级：P0**  
**用途：** 把发送、确认、丢失、超时、同块重传与去重讲清楚。

泳道：

```text
任务队列 | 调度器 | 星上发送端 | 随机信道 | 地面接收端 | 证据记录器
```

至少包含两条路径：

1. 正常发送→接收→ACK→完成；
2. ACK丢失/超时→同块重传→接收端去重→完成。

视觉：

- 正常消息深轨道蓝；
- 数据包冰川青；
- ACK健康青绿；
- 丢失/超时矿物珊瑚；
- 重传柔和琥珀；
- 关键状态转移写事件名，不写长代码。

来源：协议实现、事件类型和验收手算。机制图不得声称真实卫星链路已经部署。

## 15. 最终裁决

本项目的图表不能走两种极端：

1. 只放文字、表格和公式，导致技术完整但评委难以快速理解；
2. 为了“丰富”而生成大量没有证据、没有复现代码的彩色图形。

正确路线是：

> 用 C 的机制图建立业务与系统全貌，用 A 的数据与模型图解释AI的作用和边界，用 B 的协议与实验图证明6G调度链路、公平验证和失败行为，再由 C 统一视觉、引用与材料口径。

最终每张图都必须同时满足四点：**有问题、有事实、有审美、有复现。**

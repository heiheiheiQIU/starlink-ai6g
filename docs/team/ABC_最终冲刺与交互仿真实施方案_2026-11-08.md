## 1 执行摘要

### 1.1 最终作品必须同时成立的四件事

1. **业务成立**：作品解决6G星地链路窗口、能源和异构任务争用下的通信调度问题。
2. **技术成立**：AI读取健康、任务与链路状态进行条件化价值评分，约束层负责动作可行性，协议层负责发送、确认、重传和去重。
3. **工程成立**：用户能够修改仿真条件，启动真实仿真代码，持续读取事件，看到任务、链路、能量、评分、约束与结果随运行变化。
4. **证据成立**：正式实验与交互实验永久隔离，所有对外数字可追溯到 `claim_id → run_id → 输入/模型/代码SHA → 原始事件 → 统计结果`。

### 1.2 本轮最重要的新增目标

把当前“固定演示主界面加局部在线运行面板”升级为：

> 由真实仿真事件驱动、参数可配置、过程可回放、策略可比较、结果可追溯的AI+6G星地通信调度实验平台。

这不是生产级真实卫星测控系统，也不能这样宣传。其准确定位是：

> 面向真实工程条件设计的、合成数字场景驱动的工程验证平台。

### 1.3 不得被新增前端工作挤掉的原关键路径

1. formal_v2生成前回执、180条候选输入、第二阶段三方签核、正式冻结；
2. EDF、Value、Learned三策略共540个唯一策略运行；
3. 配对统计、四档裁决、失败案例和换机复现；
4. 报告v3正式结果、图表、公式、引用和版式终检；
5. 15页主讲PPT、5页答辩备查、讲稿和PowerPoint实机终检；
6. 3至5分钟视频、离线演示包、匿名检查、AI使用说明和最终哈希。

## 2 反复论证后的方案裁决

### 2.1 方案一：继续固定数据演示

优点：稳定、开发量小。
缺点：参数变化不进入仿真，动效与结果不变化，评委无法验证工程真实性。
裁决：**否决**。只能保留为断网兜底，不得作为作品主形态。

### 2.2 方案二：追求真实卫星和真实6G生产平台

优点：目标宏大。
缺点：缺少真实遥测、真实星地链路、设备认证、安全体系、生产运维和可验证部署；四天内不可完成，也不可诚实宣称。
裁决：**否决**。只在落地路线中写为影子试点和后续阶段。

### 2.3 方案三：正式评测与交互仿真双轨共核

结构：

```text
同一仿真内核与事件合同
├─ sandbox交互实验轨：参数可编辑，新建run，真实事件，可回放比较
└─ formal_v2正式评测轨：输入模型统计规则冻结，禁止编辑，三方签核
```

优点：既能展示真实代码运行和差异化视觉结果，又能保证正式实验公平与可追溯。
成本：需要B完成集成与事件可见性，C统一运行状态与页面数据源，A补齐AI事件语义。
裁决：**采用**。

提交级隔离是硬约束：

- formal的180输入、540运行和统计只能在三方签核manifest记录的 `formal_freeze_commit` 上执行；
- sandbox适配层在独立集成提交开发，输出目录、run前缀和入口均与formal分离；
- formal前端只读三方签核manifest和已登记run，不调用可编辑sandbox `POST /runs`；
- sandbox若必须修改仿真内核，formal不得复用该提交；确需复用时必须重新计算冻结对象并重新三方签核。

### 2.4 为什么不做运行中任意修改

运行中修改能量、任务或链路会改变输入语义，破坏配置哈希、复现性和策略公平比较。本轮采用：

```text
编辑配置 → 生成配置摘要与哈希 → 创建新run_id → 观察运行 → 保存 → 与旧run比较
```

允许暂停、单步和倍速播放事件；不允许把运行中篡改的状态写入正式实验。若后续增加故障注入，必须以预先登记的脚本事件作为新运行输入。

## 4 三种运行模式与统一接口

### 4.1 标准场景演示模式 fixture

用途：断网兜底、首次讲解、组件回归。
数据：明确标注“演示数据”，不得写入实验结论。
行为：可播放固定事件，但所有来源标识必须保持fixture。

### 4.2 交互仿真实验模式 sandbox

用途：评委修改参数后观察真实仿真代码产生的过程和结果。
数据：由B后端新建run生成，显示run_id、配置摘要、seed和来源状态。
行为：允许编辑配置并新建运行；不允许运行中静默改值；结果标为“交互实验”，不得自动进入正式材料。

### 4.3 正式评测模式 formal

用途：正式效果裁决。
数据：只读引用formal_v2冻结输入、冻结模型和冻结统计规则。
行为：前端禁止参数编辑，只读取 `formal_release_manifest.json`，显示签核状态、正式run和证据索引。manifest至少包含claim状态、正式run集合、模型/输入/代码/统计SHA和结果路径。manifest缺失、签核不齐或哈希不匹配时只能显示“未完成”，不得访问sandbox接口猜测结果。

### 4.4 统一运行状态

所有页面消费同一个 `run_id` 和同一个运行控制器，不允许各页面自行创建互相无关的任务。

```text
idle → queued → running → completed
                    └────→ failed
                    └────→ cancelled
```

页面刷新时恢复已有 `run_id`，不得重复POST。配置改变后旧结果保留为历史，不得覆盖。

### 4.5 增量事件读取

首选现有分页接口，不新增WebSocket：

```text
GET /runs/{run_id}/events?after={last_event_id}&limit=500
```

- POST取得run_id后，状态轮询与事件读取使用两个独立循环；
- 运行时间足够时每750毫秒读取新增事件，服务压力高时可放宽到1000毫秒；
- 只追加 `event_id > last_event_id` 的事件；
- 事件重复必须去重；
- 每轮按 `has_more/next_after` 连续排空，不能假设单页500条足够；
- 网络失败保留最后已确认事件并显示离线状态；
- 重连从最后确认的 `next_after` 恢复；
- completed后执行最后一次排空，再读取results和export；
- failed/cancelled不得显示partial为正式结果。

若仿真在一个轮询周期内完成，不得故意减慢后端。P0要求使用完整真实事件按 `sim_time_s` 动态回放；“运行中同步增量显示”是4小时硬时间盒的升级目标。两种情况都不得宣称为真实墙钟同步。

### 4.6 事件到视觉组件映射

| 事件 | 必须更新的视觉对象 | 不允许的行为 |
|---|---|---|
| arrived | 任务队列、任务时间轴、待处理计数 | 固定显示预设任务数 |
| window_changed | 星地可见弧、窗口时间轴、速率标签 | 与窗口状态无关地持续发光 |
| decision | 候选评分、Guard检查、选中动作、原因码 | 只播放预制AI动画 |
| sent | SAT到GW链路、在途块、累计发送字节 | SAT/GW不同轨迹或错误方向 |
| dropped | 丢失标识、失败段、重试状态 | 仍显示成功确认 |
| received | 地面站接收、有效载荷累计 | 提前计入ACK完成 |
| acked | ACK返回、任务块完成、去重状态 | 未ACK即标任务完成 |
| fallback | 回退策略、原因、模型状态 | 隐藏回退或包装成AI成功 |
| snapshot | SOC/能量带、队列、事后仿真真值 | 混淆估计值和仿真真值 |

## 5 可编辑参数与视觉差异验收

### 5.1 P0参数集

本轮只开放以下高价值参数，不制作任意JSON编辑器：

| 分组 | 参数 | 建议控件 | 影响 |
|---|---|---|---|
| 任务 | 任务数2/6/10 | 分段选择 | 队列和期限竞争 |
| 任务 | 期限档8/12/18/24秒 | 选择或滑块 | EDF紧迫度 |
| 任务 | 任务权重 | 三档配置 | Value/Learned排序 |
| 能源 | 初始能量0.8/1.2/10Wh | 分段选择 | Guard与回退 |
| 健康 | 健康/退化/临界三档 | 分段选择 | HealthEstimate、评分与可行域 |
| 能源 | 储备线 | 数字输入并校验 | 可发送边界 |
| 链路 | 扰动无/mild/strong | 分段选择 | 丢失、ACK和重传 |
| 链路 | robust/fast速率档 | 选择 | 完成时间与能耗 |
| 运行 | EDF/Value/Learned策略组合 | 多选 | 决策和指标比较 |
| 运行 | seed | 非负整数输入 | 随机信道复现 |

上述轴值不得由C自行拼装为任务、窗口或健康观测。B必须提供唯一确定性构造器 `compile_sandbox_axes(axes, seed) -> ScenarioConfig` 或等价共享实现；C只提交轴值，输入哈希基于构造后的完整config。权重三档的具体向量、任务列表和HealthEstimate由B构造器固定并版本化。

P1才开放逐任务编辑、窗口起止点和协议时延；只有P0提前完成且不影响材料冻结时实施。

### 5.2 必须形成明显不同的三个黄金场景

#### S1 资源充足

- 初始能量10Wh；
- 无丢失或低丢失；
- 任务少、期限宽；
- 预期视觉：能量安全、回退少、策略可能一致；
- 讲解重点：系统不会为了展示AI而制造无意义差异。

#### S2 低能量期限冲突

- 初始能量接近储备边界；
- 高低权重任务竞争同一窗口；
- 预期视觉：更多Guard拒绝、fast减少、robust/idle或回退增加、能量曲线接近阈值；
- 讲解重点：健康状态改变通信动作可行域。

#### S3 ACK丢失与重传

- ACK丢失概率提高；
- 包含至少一个多块任务；
- 预期视觉：sent后ACK缺失、超时、重传锁、同块重传、去重、效率下降；
- 讲解重点：AI选择之后仍需协议闭环。

### 5.3 差异真实性门禁

- 不要求每个场景都出现Learned优于规则；
- 相同动作必须显示“本状态下策略决策一致”；
- 不同配置至少在输入哈希、事件序列或一个合法指标上产生可解释差异；
- 在相同完整config、seed、policy/model SHA、code revision和依赖锁下，关键事件摘要与结果必须可复现；
- 前端不得为了视觉差异随机改色、改数字或插入不存在的事件。

## 16 最终成功标准

评委在五分钟内应当能够确认：

1. 这是6G星地通信资源调度，不是把寿命预测硬贴到通信上；

6. 报告、PPT、视频、前端和代码共享同一事实源；
7. 当前是可信的工程验证平台，并具备向半实物和影子试点演进的清晰接口。

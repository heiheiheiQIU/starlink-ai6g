# 星地智调前端 · 信息架构与视觉设计规范（v5，用户裁决版）

版本：v5，2026-10-29，成员C。**v4 一站式范围经用户再次确认维持不变**（见第9节裁决记录）；本版吸收 GPT 前端 MVP 建议稿中的有效设计建议，驳回其范围回滚。状态：作为 C-N1 交付与正式工程实现的依据。配套可点击草图：`docs/design/v4_sketch.html`（契约样例，浏览器直接打开；工作区副本见 `前端草图/星地智调_前端布局草图_v4_工程详情与AI助手_2026-10-28.html`）。

依据：06完整方案§8、C任务书、C_DeepSeek手册、00协作接口与09手册字段、H00合同候选（docs/contracts/README.md）。前端不自算科学指标，不训练模型，fixture 永久标注。

## 1 平台信息架构（一站式）

侧边栏两个分组，共 6 个入口：

| 分组 | 入口 | 用途 |
|---|---|---|
| 主流程 | 流程主舞台 | 六步层层递进的默认体验（评审演示主线） |
| 主流程 | 总览 | 系统链路大图＋当前实验状态＋倒计时 |
| 主流程 | AI 助手 | 独立对话页：RAG 知识库＋引用来源卡 |
| 工作台 | 对照实验台 | 同配置双策略同轴对比 |
| 工作台 | 实验与证据 | run 列表、事件日志、证据索引、导出 |
| 工作台 | 数据与模型 | 冻结资产台账（来源/SHA/许可）、模型卡 |

设计原则：**一层只有一件焦点事；主舞台最中心最大；"下一步"永远可见；每步完成留下可追溯产物并伴随动效。** 次要信息向两侧（步骤子侧栏、上下文面板）与下方（工程师详情区）收敛。

## 2 流程主舞台：六步规格

流程条：①任务到达 → ②窗口预测 → ③AI评分 → ④约束解码 → ⑤发送/确认 → ⑥评估与证据。已完成✓、当前高亮脉冲、下一步按钮金色脉冲；支持**自动演示模式**（每步约3秒，评审/录屏用）。

### 2.1 每步三层布局

- **主舞台（中心，最大）**：当前步骤的唯一焦点可视化；
- **步骤子侧栏（左220px）**：本步工程上下文（参数/状态/计数），工程师视角；
- **上下文面板（右250px）**：是什么/为什么/效果三件套＋本步产物＋流程进度；
- **工程师详情区（舞台下方，可折叠）**：本步全字段表/日志，含"复制JSON"。

### 2.2 每步交互与动效规格

| 步骤 | 主舞台 | 真交互（每步≥2） | 动效/生成 |
|---|---|---|---|
| ① 任务到达 | 星上队列 | 添加三类业务任务；点击任务查看字段 | 任务块掉入队列、cache计数更新 |
| ② 窗口预测 | 0—600s 时间轴 | 拖拽窗口条；扰动档位；查看预测剖面 | 窗口条延展、预测虚线呼吸 |
| ③ AI评分 | 候选评分卡 | 运行评分；切换任务；查看因子分解 | 因子条形生长、分数计数滚动、最高分金脉冲 |
| ④ 约束解码 | 约束检查清单 | 切换 robust/fast/idle；查看字节配额 | 检查项逐条打勾、否决红闪抖动、配额计算 |
| ⑤ 发送/确认 | 轨道链路舞台 | 播放/单步/倍速；注入ACK丢失 | 光束脉冲、块飞行、ACK回传、重传去重提示 |
| ⑥ 评估与证据 | 指标与证据卡 | 生成实验报告；点指标看定义；导出 | 数字滚动、图表逐点绘制、证据卡逐个弹出 |

### 2.3 每步子侧栏与工程师详情内容

| 步骤 | 子侧栏（工程上下文） | 工程师详情区 |
|---|---|---|
| ① | 队列统计（条数/cache/最高权重/最早期限）、入队事件计数、data_location | Task 全8字段表（含单位） |
| ② | Window 摘要（id/start/end/速率/误包/forecast_version）、预测误差提示 | rate_profile/loss_profile 逐点剖面表 |
| ③ | 模型卡摘要（版本/结构/特征/候选数）、候选分数mono列表 | 任务×模式评分矩阵＋feasible列 |
| ④ | guard检查清单（code列）、配额公式、guard版本 | ConstraintCheck明细＋Action JSON样例 |
| ⑤ | 在途状态机（queued→inflight→acked）、事件计数、能量账本、重传计数 | events.jsonl 事件流（event_id/policy/sim_time/type/energy/reason） |
| ⑥ | 指标定义速查、分母说明、证据文件列表 | results.json 指标明细＋metric_reasons（null+原因语义） |

字段与单位一律来自 H00 合同（docs/contracts/README.md），不允许前端另造。

## 3 AI 助手对话页规格

- 布局：左＝会话列表与快捷命令（流程解释/合同字段/故障排查/证据边界，支持 `/查 <字段>`、`/解释 <错误码>`、`/指标 <名称>`）；中＝对话流（打字中动效、回答带引用chip）；右＝**引用来源卡**（文档名＋段落摘录＋路径/行号）＋RAG 知识库索引状态。
- 知识库（RAG 来源，仅限已核验文档）：06方案、09手册、docs/contracts/README＋CHANGELOG、00协作接口、Require赛事原件、evidence_index、A1/R0/H00证据、B工作路线；**6G.txt 只作线索，不作为权威引用**。
- 管道示意：ingest → chunk → embed → retrieve → answer；回答必须带引用，无证据明确拒绝编造。
- 硬纪律：不生成实验数字、不解释未验证的算法内部、三级降级（LLM→关键词话术→拒绝）。
- 落地规划：B 端 R5 之后新增 `POST /assistant/chat`；RAG 索引独立目录；离线演示回退关键词话术库。悬浮球（全局右下）与其共用同一后端与知识库。

## 4 状态矩阵（十态与落点）

loading/empty/fixture/queued/running/completed/failed/fallback/history_replay/offline：

| 状态 | 落点 |
|---|---|
| fixture | 全局顶部琥珀徽章"契约样例·非实验结果"（任何页面不得移除）＋数据旁标识 |
| queued/running | 流程页/实验列表显示状态，不展示最终指标；progress 允许 null |
| completed | 才允许展示最终指标并链接 results |
| failed | 显示错误码与恢复动作，保留 partial，不伪成功 |
| empty | 队列/列表空态（图标＋说明＋下一步） |
| loading | 骨架屏/打字中动效 |
| fallback | 模型缺失/NaN → 规则回退事件与原因码展示 |
| history_replay | 回放徽章＋暂停/单步/倍速仅作用于日志，与现场重算显著区分 |
| offline | 字体/图标/图表零CDN，断网可演示并明确提示 |

对应 T01—T20 必测矩阵（C_DeepSeek手册§5）。

## 5 字段→组件映射（合同 → 界面）

| 合同类型 | 界面组件 |
|---|---|
| Task | 队列条目、任务详情表（①步） |
| Window | 窗口条/甘特、剖面表（②步） |
| CandidateScore | 评分矩阵、候选列表（③步） |
| Action/ConstraintCheck | 约束清单、决策理由、Action JSON（④步） |
| Event（sent/received/acked/…） | 链路动画、事件流表（⑤步） |
| snapshot.data | 能量区间图（只读 snapshot，不用 event.energy_Wh 当剩余能量） |
| PolicyResult/metric_reasons | 指标卡、对比表、证据抽屉（⑥步） |
| RunResult/RunStatus | 实验列表状态、run头 |

规则：`decision.data.latency_ms` 只读线上名；`evaluation_truth` 只作事后评估展示；图表按 policy_id 隔离。

## 8 证据纪律（前端侧）

- 全部契约样例数据保持琥珀徽章；正式演示只允许可追溯 run_id 的真实结果；
- 指标数字可点开证据抽屉（定义/单位/分母/run_id/配置哈希/源文件/可支持与不可支持结论）；
- 修改配置必须新建 run，旧结果标"历史/失效"；页面不得重算科学指标；
- 录屏/截图不得含学校、导师、账号与绝对路径（T20）。

## 9 用户裁决记录（2026-10-29，v5 相对 GPT 建议稿）

GPT 于 10-29 产出前端 MVP 收敛建议稿（未提交的 `docs/superpowers/specs/2026-10-29-c-frontend-mvp-design.md`），用户裁决：**纠正回 v4 已确认范围，同时吸收有效设计建议。**

### 9.1 驳回（以 v4 为准，理由）

| GPT 建议 | 裁决 | 理由 |
|---|---|---|
| 收敛回"两个主页面"，六步仅作驾驶舱内流程状态 | 驳回 | 用户已确认 v4 一站式五区结构（主流程3＋工作台3），六步主舞台＋每步子侧栏＋工程师详情区保留 |
| AI 助手对话页、RAG、悬浮球列为"非目标/最后才做" | 驳回 | 用户明确要求的加分项，保留为正式范围（仅落地顺序靠后） |
| v4 草图定性为"历史参考，不再称正式实现规格" | 驳回 | v4 是用户确认的设计基线，作为实现依据保留 |

### 9.2 吸收（写入本规范）

1. **字号硬规则**：正文≥14px、关键数字≥24px，正式工程一律执行（草图探索字号不照搬）；
2. **在线/事后分区**：在线舞台只显示可观测预测；"真实值"只在完成后的事后评估区以 `evaluation_truth` 标签展示，禁止在线自由切换预测/真实；
3. **六步=解释链语义**：流程条用于浏览一条可追溯的解释链（任务→窗口→评分→约束→发送→评估），不宣称"整个 run 生命周期永久完成"；回看允许，回看不伪装重算；
4. **配置预设**：首版运行配置用 B 提供的固定场景预设（R2 `configs/scenarios/*.json`），C 只展示摘要并原样提交；通用参数编辑器延后到 B 冻结配置 Schema；
5. **Observation 上游依赖**：真实联调前由 C 向 B 提交接口需求（扩展事件快照或新增只读观测接口，走合同变更流程）；B 未交付时只展示合同已有事件摘要，不从零散事件推测完整观测；
6. **模块边界**：`contracts.ts / api/runs.ts / domain/runView.ts / state/useRun.ts / pages / components(evidence+run+compare) / styles/tokens.css / fixtures`；不引入全局状态库；
7. **反目标**：不以页面数量/动效/"AI"文案制造完成度假象；不串流 policy；queued/running/failed 不展示最终指标；匿名纪律；
8. **失败降级**：API未就绪→显式fixture；轮询失败→保留最后状态；图表不可用→同字段表格兜底；
9. **工程师详情区默认收起**：首版折叠，避免抢占评审主叙事，可展开对照调试；
10. **验收清单**：fixture徽章全屏可见、状态语义、policy隔离、null+reason 与实测0、参数变更失效、刷新恢复、证据抽屉、双分辨率/离线/reduced-motion、构建+浏览器截图记录。

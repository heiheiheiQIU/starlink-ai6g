```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe -m uvicorn backend.api.main:app --host 127.0.0.1 --port 8000 --workers 1
```

另一终端：

```powershell
$body = Get-Content -Raw -Encoding utf8 tests/fixtures/api/request.json
$created = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/runs -ContentType application/json -Body ([Text.Encoding]::UTF8.GetBytes($body))
$runId = $created.run_id
Invoke-RestMethod "http://127.0.0.1:8000/runs/$runId"
Invoke-RestMethod "http://127.0.0.1:8000/runs/$runId/events?after=0&limit=500"
# status=completed 后再执行：
Invoke-RestMethod "http://127.0.0.1:8000/runs/$runId/results"
Invoke-WebRequest "http://127.0.0.1:8000/runs/$runId/export" -OutFile "runs/$runId.zip"
```

服务根目录固定为 runs/api；只能由一个 uvicorn worker/实例持有，不使用 --reload 或多个服务共享该目录。该首版面向本机127.0.0.1，不是公网多租户部署。

## 请求与接口

POST 请求体是冻结 RunRequest：schema_version、config、policy_ids、seed。config 使用现有 RunConfig 的完整内联场景，actions 必须为空，不能提供非空 policy_runtime。不是任意文件路径，也不自动加载模型。tests/fixtures/api/request.json 为可提交配置。

| 请求 | 行为 |
|---|---|
| POST /runs | 202，queued 与新 run_id；最多两种不同规则 edf/value |
| GET /runs/{id} | queued/running/completed/failed 状态、实际进度或null、active_policies、error |
| GET /runs/{id}/events?after=0&limit=500 | EventsPage；最大limit=2000；next_after用返回的末event_id；完成后继续读至has_more=false |
| GET /runs/{id}/results | 完成的完整 RunResult；运行中、失败均409，details.status说明当前状态 |
| GET /runs/{id}/export | 完成后ZIP；仅包含同一run允许列表文件，相对路径；未完成409 |

错误体统一 code/message/details：404 RUN_NOT_FOUND、422 INVALID_CONFIG、409 RUN_NOT_COMPLETE、429 CAPACITY_BUSY、500 INTERNAL_RUN_ERROR。不根据message字符串判断逻辑。

每次POST产生新run；页面刷新应保存run_id后用GET恢复，不能重新POST。首版无提交幂等键、暂停或单步后台接口。

## 执行、口径与失败恢复

- 最多一个活跃比较运行，每run一个spawn进程；同run的最多两条策略顺序执行，环境和评分器完全独立，使用相同场景。进度表示已完成策略比例；running只列当前策略。
- API时域最多240秒、最多128任务/每类128窗口；工作进程壁钟上限120秒。超限配置422；运行超时、崩溃或服务停止记failed，不发布正式结果。
- 当前仅确定性、零实际随机损失的合成环境；seed被完整记录，同seed科学结果可复算，未实现随机信道抽样。decision耗时是实际壁钟值，不要求字节级重现。
- 同run根events.jsonl是权威事件流，event_id在run内递增；各策略的sim_time_s可重复，用policy_id分流。子目录原始事件保留本地编号，仅用于审计，不能拼接后直接喂页面。
- 运行中的事件按已完成策略整批发布；首条策略尚未结束时返回空页，继续轮询同一游标。has_more=false只表示当前快照无更多事件，不表示run已完成。
- 完成状态最后写入；结果、manifest和全部策略产物先落盘。Windows短时读锁触发有界重试。重启将遗留queued/running和未完整初始化记录标failed，已完成结果仍可恢复读取。
- config.json保存不可变完整RunRequest；顶层config_hash覆盖配置、策略列表及seed，input_hash覆盖完整ScenarioConfig；manifest保存API源码SHA和产物SHA，子策略manifest保留仿真/策略源码SHA。
- 导出使用允许列表并拒绝符号链接/目录联接。失败运行保留诊断和部分产物，但没有正式下载包。

## C 的三个接收检查

1. 提交request.json，保存run_id，刷新后GET恢复；最终两个policy_id各自显示，不能混流。
2. limit=3逐页读取，检查event_id连续、不重复，完成后最后一批读完；用RunResult直接显示指标，energy曲线从snapshot取值。

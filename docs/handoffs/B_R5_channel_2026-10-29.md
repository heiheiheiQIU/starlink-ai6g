## 行为与接口

ScenarioConfig新增可选channel：`{version:"time-indexed-sha256-v1",seed,step_s:0.25,ack_loss_prob:0.0}`。没有channel时沿用R3零实际误包配置，旧调用继续有效。实际窗口loss_profile的两档概率仅在显式channel下启用。

- 外部随机值是SHA256(version,seed,stream,time_index)的前53位归一化值；时间格按十进制字符串的精确分数取整。相同seed、时间、stream必定相同，不依赖策略、任务、块号、模式或发包次数。
- 数据在发送起点取样，概率取实际窗口在该起点的loss_profile；这是块级起点采样假设，不是逐bit信道积分。robust/fast共用外部随机数但阈值可不同，不能声称两模式独立。
- ACK使用独立stream，在预计ACK到达时刻取样，概率取channel.ack_loss_prob。时间格内相关，默认每0.25秒更新；不是每包独立抽样。
- 数据丢失发出dropped/DATA_LOST_CHANNEL，不生成received或ACK；只等超时。数据成功但ACK丢失发出dropped/ACK_LOST_CHANNEL，仍计接收耗能，下一次重传去重，业务成功以首次完整接收为准。
- Observation不含channel seed、真实随机值或接收端状态。预测loss_profile仍可见；规则评分沿用现有定义，不宣称已进行风险最优调度。现有枚举教师遇非零预测损失仍明确UNSUPPORTED_LOSS。
- CLI RunResult.seed记录实际channel.seed，manifest保存channel配置；完整ScenarioConfig进入input_hash/trace_hash。HTTP请求有channel时要求channel.seed==request.seed，不一致422。无channel的seed仍只记录。

## 可独立运行的对照

```powershell
New-Item -ItemType Directory -Force runs/r5 | Out-Null
.\.venv\Scripts\python.exe -m backend.experiments --matrix experiments/test_matrix.json --output runs/r5/my_pilot --limit 2
# 全部18工况×10轨迹（仅两条规则，不包含AI/优化器）：
.\.venv\Scripts\python.exe -m backend.experiments --matrix experiments/test_matrix.json --output runs/r5/my_matrix
```

输出：status.json、manifest.json、summary.json、per_run.csv、configs/以及每条轨迹的runs/<trajectory>/edf与value完整运行包。每个新批次生成新run_id，同一轨迹的两个policy共用run_id、输入和seed。失败保留partial文件和failed状态，不把已完成条目删掉或包装成全矩阵成功。

参数均为新增合成验证假设，非实测或校准结论：

| 项目 | 设定 |
|---|---|
| 时域、窗口、步长 | 24秒；[0,26)；2秒决策步 |
| 负载 | 2/6/10任务，到达间隔2秒，每任务1或2个1024byte块 |
| 期限、权重 | 到达后6或10秒，上限24；循环权重1/2/3 |
| 储能 | 初始0.8/1.2/10Wh；容量20Wh；reserve0.5Wh |
| 功耗、速率 | 沿用R3配置：背景36W、发射36/72W、速率8192/16384bit/s、ACK接收8W |
| mild误包 | robust0.05 / fast0.12，ACK0.02 |
| strong误包 | robust0.2 / fast0.4，ACK0.12 |

任务生成使用独立`tasks-v1`seed命名空间，不消耗信道序列。所有方法共享健康估计；本轮使用准确SOC/容量，充足能量档构成“额外健康预测无益”的反例。以上设置未按策略收益调优，但也未完成A的划分签核，不算正式AI测试集冻结。

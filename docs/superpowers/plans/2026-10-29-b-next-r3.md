> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在已交付的R2发送环境上，完成接收、ACK、超时重传、网关去重和可手算的业务交付评价，向A/C交付一次实际执行的合成运行。

**Tech Stack:** 现有Python 3.12、Pydantic、pytest；本阶段不增加求解器、Web框架或训练依赖。

**Spec:** 只读研发包《09_三人项目实施方案_详细执行与交接手册》§7、15.3、16、17；《06_AI6G星地智调_完整方案_2026-10-26》§6.4；《成员任务书/B_通信仿真与系统执行任务书》B1/B3；仓库`docs/contracts/FREEZE_2026-10-29.md`与`docs/handoffs/B_N2_R2_2026-10-29.md`。09补充优先；下面明确标为建议的内部实现细节不是已有团队合同。

## Global Constraints

- 保持H00 schema_version="1.0"及公共签名；不改legacy、A健康/训练源码、C前端源码。不自动合并整个A/C分支。
- 最大有效块1024byte，最后块可短；数据头32byte；ACK16byte；单在途；时间s、功率W、能量Wh、速率bit/s，1Wh=3600J。
- 已接收与星上已确认是两种状态。只在ACK到达后扣星上remaining_bytes；网关以(task_id, block_id)去重。
- 完整任务成功以最后一个有效块首次接收时刻<=deadline判定；晚ACK不撤销已发生的业务成功。
- 窗口[start,end)，数据在end前完成发送；关窗不删除传播中的数据；未送达ACK遇关窗丢失，ACK发射需可见窗口。
- 时序：截至当前时刻的接收/ACK与到达→过期判定（now>deadline）→观测→决策→推进。ACK与超时同时发生时先处理有效ACK，避免假重传。
- 未来任务、实际未来信道、网关去重集合及真实能量不进入Observation。全程保持有限数值、实例隔离和clip前违例证据。
- 本阶段保留确定性、零随机误包；用真实窗口关闭触发ACK丢失。不把随机丢包、公平多策略或完整安全guard宣称已实现。
- 接收/控制能耗与数据发射能耗各记一次；背景包含接收待机，新增活动接收功率必须是超出背景的增量。ACK开销不能计为有效载荷。
- 只有接收人可写accepted；R2历史证据不改写成R3结果；原契约fixture仍是格式样例，不能直接改behavior_verified冒充执行证据。

## Review Focus

1. 窗口关闭发生在数据发送完成后、ACK前：数据可到达，ACK可丢，下一窗重传不重复收益（Task 2）。
2. 接收恰等于deadline、ACK晚到，以及ACK与超时同刻：成功口径和重传状态一致（Task 2）。
3. 大步长跨多个内部事件、浮点末位边界、拆步/整步：时间不越界且能量账目一致（Task 1/2）。
4. 重传、最后短块和部分接收：业务成功、星上缓存、有效字节、控制字节分别计量（Task 1/3）。
5. 未到期/未来任务、零成功、导出中断：不稀释分母，不伪造0能效或completed（Task 3/4）。

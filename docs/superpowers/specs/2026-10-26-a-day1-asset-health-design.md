# A角色第一阶段设计：旧资产审计与健康输入

## 目标

在不修改 `assets/legacy_battery` 原件的前提下，建立可追溯的旧电池资产审计、严格失败的最小健康推理入口，以及供B接入的健康数据合同。第一阶段只证明“数据和权重能否被可信使用”，不训练通信调度策略，也不声称产生新的通信实验结果。

## 工作区与证据边界

- 新代码与文档位于 `D:\ict\星地智调`。
- 只读参考包位于 `D:\ict\星地智调_团队研发包_2026-10-26_v3`。
- 旧冻结预测、旧评估指标和旧 `quick` 结果仅作历史证据。
- 所有审计结论必须附源路径、SHA256、检查命令和未验证边界。

## 采用方案

采用“引用只读资产、在新仓库建立适配层”的方案：不复制或修改legacy源码；审计工具从配置指定的参考包读取文件；健康适配器只接受已经完整到达且 `available_at_s <= now_s` 的窗口。模型输出先保持为可解释的原始归一化预测；未证明无泄漏的原生RUL还原不进入在线接口。

未采用两种备选：复制整套旧工程会造成来源重复和误改风险；直接在legacy内修补会破坏历史证据和团队接口边界。

## 组件

1. `training/inspect_legacy.py`：读取manifest、NPZ和checkpoint元数据，输出机器可读审计结果；不训练、不覆盖旧文件。
2. `backend/health/legacy_adapter.py`：严格校验窗口长度、特征顺序、可用时间和有限数；模型不可用时返回受控错误，不静默降级。
3. `tests/test_health.py`：先覆盖未来窗口、缺特征、缺权重、非有限输出、批量尺寸和不同输入真实前向。
4. `docs/asset_audit.md`、`data/manifests/legacy.csv`、`data/manifests/assets_audit.json`：分别保存人读结论、来源清单和机器读结构。
5. `docs/health_contract.md`：说明RUL、SOC、容量、能量边界和 `available_at_s` 语义，供B验收H01。

## 数据流

只读包 manifest与资产 → 审计器验证SHA/结构 → 选择与模型严格匹配的标准化NPZ窗口 → 适配器检查时间与特征 → 严格加载checkpoint → 输出原始预测和来源元数据 → B的健康观测层决定是否使用或以 `null + reason_codes` 降级。

标准化参数未闭合时，仅允许对交付NPZ中的标准化窗口做最小前向；不得把新原始遥测直接送入旧模型。

## 已知冲突的处理

- 源NPZ的585个标签与 `public_battery_fixed.csv` 完全一致，而旧预处理入口读取 `public_battery.csv`。审计报告明确记录，不修改旧入口。
- legacy `time_index` 实际记录窗口起点。新接口把预测可用时间按窗口末端计算，并同时保存legacy起点索引以便追溯。
- 未找到持久化scaler。第一阶段不重建新原始窗口的标准化链；若后续重建，须由训练run重新拟合并版本化。
- checkpoint只有在类、键、张量形状全部严格匹配时才判可加载；禁止 `strict=False`。

## 错误处理

缺文件、SHA不符、特征顺序不符、窗口未收齐、未来可用时间、NaN/Inf、checkpoint不匹配均产生稳定错误码和可读原因。RUL不可用时返回 `null`，不填0；错误不得被标记为成功推理。

## 测试与验收

遵循测试先行：每项行为先写失败测试并确认因缺少实现而失败，再写最小实现。H01至少包含成功、RUL缺失、非法输入三份样例和对应日志。完成声明前运行完整 `pytest tests/test_health.py -q`，并记录Python、PyTorch、NumPy版本及CPU设备。

## 本阶段不做

不实现B的通信环境、教师优化器、guard或API；不训练新策略；不安装大型原始NASA数据；不恢复反作用轮；不生成比赛收益结论。

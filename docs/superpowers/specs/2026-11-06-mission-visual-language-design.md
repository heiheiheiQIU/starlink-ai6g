# 星地智调任务控制台视觉与产品语言设计

## 意图

把现有“科技感演示页面”升级为可信、克制、可发布的星地任务控制台：AI+6G 领域专家能够识别技术边界，非本方向评委也能在第一屏理解业务对象、当前状态和下一步动作。

## 目标

- 建立统一的航天任务控制台色彩语法，减少荧光紫、泛光和多种高饱和色同时竞争。
- 用一张低对比星地主题背景形成产品识别度，但不影响数据阅读与交互。
- 建立“用户可读名称＋工程标识”的双层措辞体系。
- 保留数据来源、演示数据、开发期运行、正式结果之间的严格边界。
- 七个页面共享同一视觉基底、状态颜色和数据来源表达。

## 非目标

- 不改变后端接口、合同字段、科学指标和正式实验口径。
- 不把演示数据包装成真实结果，不隐藏尚未接入或尚未签核的状态。
- 不将平台改造成电影大屏、营销落地页或泛 AI 紫色界面。
- 不删除专家所需的 `run_id`、SHA、接口路径等信息；它们下沉到工程详情层。

## 视觉决策

采用“克制的航天任务控制台”路线。

### 色彩语义

- 基底：轨道深蓝 `#081521`、石墨蓝 `#0d2232`、雾蓝灰 `#70879a`。
- 通信与当前操作：冰川青 `#58b8c7`，只表达星地链路、选中态和主操作。
- 健康与通过：低饱和青绿 `#63b89a`。
- AI 评估：灰蓝紫 `#7f91b8`，降低“生成式 AI 紫”的视觉联想。
- 风险与等待：柔和琥珀 `#d5a557`。
- 失败与阻断：矿物红 `#d67272`，仅在明确故障时使用。

颜色不得单独承担语义，必须同时提供文字或图标。非活动组件不使用持续泛光。

### 背景资产

生成一张 16:9 无文字、无人像、无界面框的横向背景：地球暗色弧面、一个低轨卫星剪影、两条克制的星地通信弧线、大片负空间。整体低对比、哑光、半写实工程可视化风格，主光色为深蓝与低饱和青绿，不使用霓虹紫和密集星点。

资产用于 `.app-main::before`，覆盖浅色外壳后的统一工作区；页面再叠加深蓝透明遮罩。背景只建立主题，不承载事实或数据。

### 层级

1. 页面背景：主题资产＋深蓝遮罩。
2. 顶栏与数据来源条：半透明深色玻璃层，明确当前页面和数据状态。
3. 主工作区：石墨蓝面板，边框由主题色轻微透射。
4. 数据卡与操作区：高对比、低泛光；交互态才提升亮度。

## 产品语言决策

### 双层表达

- 第一层面向评委与业务人员：使用“标准场景演示、任务实例、安全约束决策、最优决策标注、结果与追溯”等词。
- 第二层面向工程师：在详情、括号或等宽字体中保留 `fixture`、`run_id`、`Teacher Solver`、`Guard`、`Observation`、SHA 等标识。

### 统一映射

| 研发内部词 | 用户第一层用词 | 工程层保留 |
|---|---|---|
| FIXTURE / 契约样例 | 演示数据 / 标准场景演示 | `source_kind=synthetic_fixture` |
| run | 任务实例 | `run_id` |
| 教师标签 / Teacher | 最优决策标注 / 标注求解器 | `Teacher Solver` |
| 约束解码 / Guard | 安全约束决策 | `Guard` |
| EvidenceBundle | 结果与追溯包 | `EvidenceBundle` |
| 冻结 | 版本锁定 | SHA、manifest、frozen 状态 |
| 哈希覆盖 | 完整性校验 | SHA256 |
| 真实运行 | 在线任务执行 | POST/GET 接口 |

“演示数据”不是贬义，应紧邻说明“用于展示流程与数据结构，不作为实验结论”。“正式结果未完成”保持原口径。

## 动效决策

- 保留卫星链路、ACK、步骤推进和运行扫描动效。
- 删除非关键按钮的永久脉冲；只有运行中、告警或当前链路允许循环动画。
- 所有动效遵守 `prefers-reduced-motion`。
- 背景图不做视差，不造成信息漂移。

## 验收

- 1366×768 与 1440×1000 下无横向溢出，首屏可见当前页面、数据状态、核心工作区和主操作。
- 七页均显示数据来源类别；不出现未解释的 `FIXTURE`、`MIXED`、`DEV-RUN`。
- 第一层不出现孤立的“契约样例、教师标签、约束解码、run”措辞。
- 真实/在线状态与演示数据状态不得因换色混淆。
- 前端测试、TypeScript 检查和生产构建全部通过。

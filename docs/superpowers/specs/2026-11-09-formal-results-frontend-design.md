# 正式实验结果前端接入设计（C线）

日期：2026-11-09
状态：前端框架已实现；正式数据尚未生成，结论保持“未完成”

## 1. 目的与边界

策略评估页需要同时容纳两类完全不同的证据：

1. 单次沙盒运行：用于交互、事件回放和参数敏感性演示，不支持总体增益结论；
2. formal_v2正式配对实验：180条冻结轨迹、3个策略、540次策略运行，用于正式结论。

二者不得混用。前端不得手填实验数字、不得把沙盒结果冒充正式结果、不得把
“未检出稳定差异”改写为“等效”。Hybrid不进入formal_v2。

## 2. 结论层级

每个主比较（Learned–EDF、Learned–Value）同时显示：

- `statistical_verdict`：分析程序根据均值和95% CI得到的内部统计结论；
- `formal_verdict`：三方结果签核后的对外结论，页面以此为主；
- `result_signoff`不是`accepted`时，正式结论只能是“未完成”。

允许的原始口径只有“胜 / 负 / 未检出稳定差异 / 未完成”。其中“未检出稳定差异”
只是未发现稳定方向，不是等效性检验通过。

## 3. 页面信息结构

- 顶部：数据范围、运行完成度、失败运行、缺失运行、失败尝试；
- 中部：两个主比较卡片，正式结论优先、统计结论从属；
- 下部：每个比较各18个工况格，显示有效配对数、缺失数、均值差和95% CI；
- 证据区：冻结清单哈希、运行索引哈希、推理时延口径；
- 解释区：明确负结果、缺失和非等效含义。

默认状态不包含任何占位数字，只显示“未完成”。配置的数据源读取失败或结构校验失败时，
页面进入“证据读取失败/证据拒绝”，不会回退到演示数据。

## 4. 数据合同与接入

唯一输入为`experiments/analyze_formal.py`对应的`formal-analysis-summary-v1`结构。
运行时由`VITE_FORMAL_SUMMARY_URL`指定只读JSON地址。未设置该变量时保持待运行状态。

正式发布前仍缺一个B线的“结果签核发布”步骤：原始分析器按设计始终输出
`result_signoff=pending`和`formal_verdict=未完成`。不得人工改JSON；应由受测试约束的发布脚本
核验A/B/C结果回执后生成发布对象，再由C把其复制到发布包的只读证据目录并配置URL。

## 5. 失败封闭规则

- 不是18格或每格不是10条轨迹：拒绝；
- 运行数不满足`完成+失败+缺失=540`：拒绝；
- 结论措辞不在冻结集合内：拒绝；
- 统计结论与总体均值/95% CI不一致：拒绝；
- 哈希不是64位SHA-256：拒绝；
- 三方未签核却出现非“未完成”的正式结论：拒绝；
- 三方已签核但正式结论与冻结统计结论不一致：拒绝；
- 配置数据源但404、断网或JSON损坏：拒绝且不显示fixture。
